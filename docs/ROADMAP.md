# 代码审查与优化路线

> 时间：2026-10 · 范围：`server/` `ui/` `web/` `tools/` 全量通读 + 14 套测试实跑
> 结论：没有"必须立刻回滚"的问题；有 3 个 P0 建议尽快修（都在安全/资源侧），
> 其余是性能与可维护性优化。

## 先说已经做得不错的地方

审之前先确认这些**不用改**，免得后来的人重复怀疑：

| 项 | 现状 |
|---|---|
| 路径穿越 | `sanitize_relative_path` + `is_path_within` 双层校验，`fsops_test` 里有 `..` 用例 |
| 口令比较 | `paths._password_ok` 用 `hmac.compare_digest`，常量时间 |
| CSRF | 写操作统一走 POST + `_check_same_origin`（`Sec-Fetch-Site` → `Origin/Referer` → 都缺才放行）；`GET /delete` 直接返回 405 |
| 安全响应头 | `nosniff` / `X-Frame-Options` / `Referrer-Policy` / `Permissions-Policy` 统一在 `end_headers` 补齐 |
| 危险类型不内联 | 只有白名单扩展名允许 `inline`，`.html` / `.svg` 一律 `attachment` |
| 断点续传 | 上传按 `(size, mtime, offset)` 记指纹，下载走 Range/ETag/If-Range |
| 并发保护 | 32 个工作位信号量，满了回 503；ZIP 流另限 4 个 |
| 磁盘耗尽 | 上传前检查剩余空间，不足回 507 |

## P0：建议尽快处理

### 1. 登录失败时把明文密码打进了日志

`server/routes.py` 两处：

```python
f'POST 登录失败 | 密码: {input_password}'        # 约 108 行
f'POST 管理员校验失败 | 密码: {input_admin_pwd}'  # 约 135 行
```

这两行会进桌面端的「访问日志」窗口，也会进控制台。共用电脑、录屏、投屏时等于把密码
摊在屏幕上（注释里写着"本机自用故意打的"，但默认部署不一定只有自用）。

**建议**：只保留长度与首字符（`密码: ********（8 位）`），要排查就再加一个
`--debug-passwords` 启动开关，默认关闭。

### 2. 聊天接口没有频率限制

`/chat/create`、`/chat/send` 是 `AUTH_PUBLIC`：同一局域网里任何人（或任何能发请求的设备）
都能刷房间、刷消息。目前唯一的约束是"每房间保留 500 条"（`MAX_CHAT_LEN`），
刷房间则没有上限，`rooms.json` 会一直长大。

**建议**：给这两个接口加一个按 `client_ip` 的令牌桶（比如每分钟 30 条消息 / 10 个房间），
超限回 429 + 中文提示；房间总数设个软上限（比如 200），到顶提示"先删旧的"。

### 3. 上传没有单文件大小上限

`server/transfer.py` 只在写盘前看剩余空间（`free < chunk + 512MB` → 507），
但单个文件多大都收。有人拖一个 200 GB 的镜像进来，会把共享目录撑满，
而且中途失败留下的临时分片没有自动清理。

**建议**：`config.py` 加 `MAX_UPLOAD_BYTES`（默认 8 GB）与 `MAX_TOTAL_BYTES`（可选），
超限在 `/upload?offset=0` 就回 413；再补一个启动时/每天的"孤儿分片"清理。

## P1：值得排期

### 4. ZIP 缓存只按时间过期，没有容量上限

`ZIP_EXPIRE_SECONDS = 600`，过期清理；但 10 个人同时打 5 GB 的包，就会瞬时占 50 GB。

**建议**：加 `ZIP_CACHE_MAX_BYTES`（超了就按最久未用淘汰，正在进行的不动），
并在桌面端状态里显示当前缓存占用。

### 5. 桌面端启动被 `schtasks` 拖住

`FileShareGUI.__init__` 里 `update_startup_btn_text()` 会同步跑 `schtasks /query`，
湿冷启动时能明显看到窗口晚出来 200~500 ms。

**建议**：把"检测是否开机自启"放进线程，回来后用信号更新按钮文案（和现在 `start_completed`
同一套模式）。同理 `is_context_menu_installed()` 虽然是读注册表，但也可以合并成一次异步检查。

### 6. HTML 页面还没有 CSP

响应头里有 `nosniff` 等，但没有 `Content-Security-Policy`。页面里唯一的行内脚本是
31 节加的那段"首屏定明暗"，其余全在同源 `app.js`。

**建议**：给 HTML 加
`default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; script-src 'self' 'sha256-<那段内联脚本的哈希>'`。
`style-src` 暂时得留 `'unsafe-inline'`（模板里有内联 `style=` 属性），后面再收敛。

### 7. SSE 每个观众占一个线程

`/chat/stream` 一个连接一个线程，`STREAM_LIFETIME=25s` 到期重连，最多 8 个槽。
10 个人同时开聊天室，第 9 个就只能收到 503。

**建议**：改成"一个广播线程 + 每连接一个小队列"的 fan-out（线程数从 O(人数) 降到 O(1)），
或者干脆退回 2 秒轮询 + `?after=` 增量（实现更简单，代价是 1–2 秒延迟）。

### 8. 超大目录一次性返回

`build_listing` 会把整个目录排序后一次性塞进 JSON。几万项的目录（比如下载目录）
在手机上会很卡。

**建议**：加 `?limit=500&offset=` 分页（前端滚动到底再拉），或服务端先按类型/首字母分区。

## P2：可选优化

| # | 项 | 说明 |
|---|---|---|
| 9 | 前端按页拆包 | 现在所有页面共用一个 89 KB 的 `app.js`。首页用不到聊天模块，可以拆成 `app-core.js` + 按页懒加载 |
| 10 | 聊天图片配额 | 目前只清理"孤儿图片"，没有按房间/总量的上限 |
| 11 | 日志过滤 | 桌面端日志只能"暂停/清空/导出"，加一个按状态码或文件名的过滤框会很实用 |
| 12 | 静态检查再进一步 | `preflight` 已能查"用了没声明"，但查不出"别名指错对象"（`var toast = Lan.api.toast`）——可以加一张"名字 → 应在的命名空间"白名单表 |
| 13 | 连接统计 | 桌面端「访问方式」卡片还有空白，可以填在线连接数 / 本次传输量（需要服务端埋计数） |
| 14 | 桌面端暗色跟随系统 | 现在只有手动切明暗，可以加一个"跟随系统"，和 Web 的 `auto` 对齐 |

## 排序建议

1. **P0-1 密码脱敏**（10 分钟，纯删日志）→ 立刻做
2. **P0-2 聊天限流**（半天，令牌桶 + 测试）
3. **P0-3 上传上限**（半天，配置 + 413 + 孤儿分片清理）
4. **P1-5 启动异步化**（1 小时，体验明显）
5. 其余按需

每一项都应该配一条回归测试：限流 → 连发 N 条断言 429；上传上限 → 造一个大文件头
断言 413；密码脱敏 → 抓日志断言不含明文。
