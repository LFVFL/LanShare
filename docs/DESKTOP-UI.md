# 桌面端（Qt 窗口）改版方案

> 现状截图：`截图\桌面端-现状.png`（离屏渲染，字体缺失所以是空白方块，只能看布局骨架）
> 样稿：`截图\桌面端-样稿.png`

## 一、现状：能跑，但看起来像 2015 年的工具

从 `ui/main_window.py` 读出来的结构：

```
📂 局域网云盘共享            ← 一行大标题 + 分割线
┌ 共享路径 ────────────────┐
│ [输入框..................] [📁 浏览] │
└──────────────────────────┘
┌ （无标题分组）────────────┐
│ 端口 [ ]   访问密码 [ ]              │
│ 管理密码 [........................]  │
└──────────────────────────┘
[🚀 启动服务] [🌐 打开浏览器] [⚙️ 右键菜单] [⏰ 开机自启]
╔ 服务信息 ══════════════════════════╗
║（一个大 QTextEdit，等宽字体）        ║
╠ 访问日志 ══════════════════════════╣
║（另一个大 QTextEdit）                ║
╚════════════════════════════════════╝
● 已停止
```

QSS 只有一层浅色：`#f8f9fa` 背景、白卡片、`#dfe4ea` 边框、`#3498db` 聚焦、圆角 6px、
字号 15/17px、按钮全是 emoji。

### 具体问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 四个按钮权重相同，主操作「启动」混在里面 | 每次开共享都要找一下哪个是主按钮 |
| 2 | 二维码藏在「⚙️ 右键菜单」里 | 手机扫码是最高频的动作，却要两步 |
| 3 | 地址用大号 QTextEdit 展示 | 想只复制某一个 IP 很别扭；窗口一小就滚动 |
| 4 | 配罿项和服务信息平铺在一列 | 没有"设置 / 运行态"的分界，停止时也是一堆灰字 |
| 5 | emoji 当图标 | Windows 上基线不齐、大小不一，且与 Web 端的线性图标体系冲突 |
| 6 | 单一浅色，无暗色 | Web 端有 6 套配色 × 明暗 × 玻璃档位，桌面端完全另一套视觉 |
| 7 | 状态只有一行「● 已停止」 | 没有"谁在访问""传输了多少"的直观感受 |

## 二、设计目标

1. **和 Web 端是一家人**：同一套配色名（indigo / emerald / rose / amber / cyan / violet）、
   同样的语义色（成功/警告/危险）、同样的圆角与间距节奏。
2. **运行态优先**：启动后一眼能看到地址、二维码、访问情况；停止时才突出设置。
3. **少控件、多留白**：卡片式分区，去掉装饰性 emoji，图标统一线性 1.5px。
4. **一次点击能完成的事不要两次**：复制地址、开浏览器、显示二维码都放在主界面。

## 三、布局方案（1040×720 基准）

```
┌──────────────────────────────────────────────────────────────┐
│ [◈] 局域网云盘            ● 运行中 · 5995 端口   [ 停止共享 ] │  ← Header 56px
├──────────────────────────────────────────────────────────────┤
│ ┌ 共享设置 ───────────────────────────────────────────────┐  │
│ │ 共享目录  [D:\共享\..................]  [选择]           │  │
│ │ 端口 [5995]    访问密码 [·······] [显示]  管理密码 [···] │  │
│ └─────────────────────────────────────────────────────────┘  │
│                                                              │
│ ┌ 访问方式 ───────────────────────────┐ ┌ 二维码 ─────────┐  │
│ │ 本机    http://localhost:5995  [复制]│ │  ┌───────────┐  │  │
│ │ 局域网  http://192.168.0.102   [复制]│ │  │   ▓▓▓▓▓   │  │  │
│ │         http://10.0.0.7        [复制]│ │  │   ▓▓▓▓▓   │  │  │
│ │                                      │ │  └───────────┘  │  │
│ │ 已连接 3 台 · 已传 1.2 GB            │ │  手机扫码直接进  │  │
│ └──────────────────────────────────────┘ └─────────────────┘  │
│                                                              │
│ ┌ 访问日志 ───────────────────────── [暂停] [清空] [打开] ─┐  │
│ │ 14:22:01  192.168.1.11  GET  /            200          │  │
│ │ 14:22:03  192.168.1.11  GET  /static/app.js 200        │  │
│ └─────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

- **Header**：产品名 + 状态胶囊（灰「已停止」/ 绿「运行中 · 端口」）+ 主按钮（启动/停止）。
- **设置卡片**：两行网格；运行中整卡置灰只读，避免误改。
- **两张并排卡片**：左「访问方式」是地址清单（每条一个复制按钮，hover 高亮），
  下面是轻量统计（连接数 / 累计流量）；右「二维码」直接显示，点一下放大。
- **日志卡片**：等宽、按状态码着色（2xx 绿 / 3xx 蓝 / 4xx 橙 / 5xx 红），右上角三个小按钮。
- 窗口最小 880×620；日志区可拖动分隔。

## 四、实现方式（Qt 侧）

| 项 | 做法 |
|---|---|
| 配色/圆角/字号 | 新建 `ui/theme.py`：token 字典 + `build_qss(palette, dark)` 生成 QSS 字符串；沿用 Web 的 6 套主色 |
| 图标 | 用 `QPainter` 画 1.5px 线性图标（`ui/icons.py`），或把 Web 的 sprite path 转成 QPainterPath；彻底去掉 emoji |
| 卡片 | `QFrame` + `objectName="card"`，QSS 里 `#card { background: ...; border-radius: 12px; }` |
| 状态胶囊 | `QLabel` + `objectName="pill"`，按状态切 `[data-state]` 等价属性（QSS 用 `#pill[state="run"]`） |
| 密码框 | `QLineEdit` + `EchoMode.Password` + 右侧「显示」小按钮切换 |
| 端口 | `QSpinBox`（1–65535），失败时红色描边 + 提示 |
| 地址清单 | `QListWidget`（无边框）或一组 `QHBoxLayout` 行；复制按钮走 `QGuiApplication.clipboard()` |
| 二维码 | 复用现有 `segno` 生成，`QLabel.setPixmap`；点击弹大图 |
| 主题记忆 | `QSettings` 存 `theme.palette` / `theme.mode`，与 Web 端默认值一致（indigo + light） |
| 日志着色 | `QTextCursor` 插入不同 `QTextCharFormat`；行数上限 2000，超出裁头部 |

现有 `FileShareGUI` 的方法（启动/停止、托盘、开机自启、右键菜单）**全部保留**，只换壳与 QSS，
所以改动集中在 `_build_ui` 与样式，不碰服务端逻辑。

### 实现时和方案的两处偏差（都是变好）

1. **二维码的地址选择**：方案里只写了"点一下放大"。实际做成了主界面直接可见的
   二维码 + 一个下拉框切换地址（默认选中"路由器那条局域网"）。原因很清楚——
   别人扫 `http://localhost:5995` 只会访问到他自己手机上，这个码是废的。
   判断"哪条才是路由器那条"的办法写在 `server/netinfo.py` 里：
   先用 UDP `connect` 到公网查默认路由（不发包），拿到地址；
   但装了 Clash/v2ray TUN 或 VPN 时默认路由会指向虚拟网卡，
   所以再按网段可信度排一遍（`192.168.* > 10.* > 172.16–31.*`），
   并把 `198.18/15`、`100.64/10`、`169.254/16` 直接判为虚拟网段垫底，
   最后用"以 .1 结尾的多半是 host-only 网卡/路由器本身"做同位次的次级排序。
   在开发机上实测：默认路由指向 `198.18.0.1`（Clash），排序后正确选出
   `192.168.1.100`。
2. **服务信息区被去掉**：原来那块大 `QTextEdit` 里的内容（目录、密码是否设置、
   地址列表）现在分别落在设置卡片、地址清单和状态胶囊上，留着就是重复。

### 顺便修掉的一个真 bug

`ui` 侧要给日志着色，就得知道每行的 HTTP 状态码。翻代码时发现
`server/http_util.py::log_message` 被一个多余的 `@staticmethod` 装饰着，
导致 `self` 实际拿到的是 format 字符串，整个方法每次都抛异常、
又被自己的兜底 `except` 吞掉——所以控制台访问日志其实一直是哑的
（桌面端日志之所以还有内容，是因为 `do_GET/do_POST` 另外调了一次
`access_logger`，且那条路径没有状态码）。

现在：去掉 `@staticmethod`；日志统一由 `send_response` 触发，
把「人话消息 + 状态码」一起丢给桌面端；顺手删掉 `runner.py` 里
那段已经不可达的旧解析代码（136 行）。
